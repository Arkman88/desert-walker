# Правила работы с проектом

При каждом изменении кода применяй навык `clean-code-performance`, установленный в `~/.codex/skills/clean-code-performance/SKILL.md`.

Сохраняй разделение генерации мира, физики, визуализации и интерфейса. Удаляй заменённый код, контролируй ресурсы Three.js и работу в игровом цикле. Выполняй соразмерный рефакторинг затрагиваемой логики, не накапливай обходные решения и не расширяй задачу до несвязанных переделок.

Соблюдай кодстайл и структуру из навыка: группируй связанные модули по игровым системам, не складывай новые системы в плоский `src`. В `main.tsx` оставляй точку входа; реализацию игрока, интерфейса и мира размещай в их модулях. При переносах обновляй импорты, пути worker, тесты и документацию.

Проверки проекта: `npm test` и `npm run build`. Визуальную проверку пользователь выполняет сам; не запускай браузер и не снимай скриншоты без его явной просьбы. Отдельно указывай отсутствие собственной визуальной проверки и замеров FPS. Не выдавай успешную сборку за подтверждение графики или производительности.

После каждой завершённой задачи обновляй `PROGRESS.md`: фиксируй результат, дату, статус механик (активна, временно скрыта, удалена) и выполненные проверки. Отделяй планы от сделанного и не отмечай визуальную проверку или замеры FPS выполненными без фактической проверки.
