# DESERT — бесшовная 3D-бродилка

Дома и новые развалины процедурно собираются из деталей хижины v4. У развалин
seed определяет разрушенные секции стен и обломки перекрытий; геометрия и
коллизии используют одну композицию. Старые сохранённые руины совместимы.

## Сенсорное управление

На сенсорном устройстве игра запускается без захвата курсора. Джойстик слева
управляет ходьбой, свайп по свободной области экрана — камерой. Можно двигаться
и поворачивать камеру одновременно. Кнопки справа позволяют бежать (удержание),
прыгать (удержание), взаимодействовать с предметами, пить, есть и обливаться водой.
При размещении постройки доступны «Поставить» и «Отмена».

Сверху находятся меню, рюкзак, карта, крафт и журнал. При открытии окна или
сворачивании страницы движение сбрасывается; после возврата нажмите «Продолжить
игру». Сенсорный режим включается автоматически, в том числе при первом касании
на ноутбуке с сенсорным экраном. Для игры мышью можно отключить «Сенсорное управление» в стартовом меню.

## Сохранения в браузере

Прогресс мира, припасы, постройки и позиция игрока автоматически сохраняются в
localStorage. После перезагрузки страницы нажмите «Продолжить игру»; через Escape
можно вернуться в меню. Сохранение привязано к браузеру и адресу сайта: HTTP,
HTTPS, localhost и другой браузер используют отдельные данные. Очистка данных
сайта удалит сохранения.

«Новая игра» требует подтверждения и сбрасывает мир, позицию и собранные осколки.
После подтверждения старая сцена завершает автосохранение, затем сбрасываются
данные и запускается новая игра без перезагрузки страницы и повторного меню.
Последняя резервная копия трёх слотов остаётся в localStorage
под ключом `desert-walker.new-game.backup`; кнопки восстановления этой копии пока
нет. Ошибка хранилища отображается пользователю, прерванный сброс повторяется при
следующем открытии. Обычный запуск сохранения не удаляет.

Старые три GLB заменены сборкой деталей v4. Ящики и обстановка используют последние модели; двери открываются/закрываются через E. Схема 19 сохраняется. Сохранены встроенные цвета вершин, пламя и свет костра остаются игровыми эффектами. При последней замене выполнена только сборка с TypeScript; тесты и браузер по просьбе пользователя не запускались.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://localhost:5173).

Сборка: `npm run build`; предпросмотр сборки: `npm run preview`.

Автоматические проверки: `npm test` — мир и коллизии, стриминг с отдельным worker, скрытый прототип ресурсов, инвентарь, выживание, крафт/навесы и сохранения. Тестовый загрузчик автоматически компилирует зависимости TypeScript во временный каталог, использует общие экземпляры модулей и удаляет каталог при завершении процесса. Ручные подстановки импортов не требуются. Проверки потребностей передают фактическую нагрузку и температурное окружение; отдельно проверяются накопление активного времени, пауза и сброс нагрузки. Проверка графики, баланса прохождением и замеры FPS выполняются отдельно.

## Управление

- WASD — перемещение
- Мышь — обзор (после нажатия «Начать путешествие»)
- Shift — бег
- Space — прыжок
- Esc — освободить курсор / пауза
- I — инвентарь с паузой; повторное I возвращает в игру
- C — отдельное окно крафта с паузой; повторное C возвращает в игру
- R — пить из фляги
- Q — облиться водой для охлаждения; во время размещения — отменить установку
- F — съесть сухпаёк
- E — открыть ящик, подобрать оставленный предмет перед собой или наполнить фляги рядом с водой оазиса
- M — открыть/закрыть найденную карту

Обливание на Q расходует 0,5 л носимой воды — две обычные порции питья по 0,25 л — и сразу снижает температуру тела на 0,3 °C, максимум до 37 °C. Жажду оно не утоляет. Сначала используются фляги, при необходимости — целые пакеты. Если воды меньше 0,5 л или температура уже нормальная/низкая, расхода нет. Во время установки построек Q только отменяет размещение. Вода и температура сохраняются сразу.

Камера расположена на уровне глаз; модель персонажа не отображается. Центральный прицел используется для наведения на мир.

## Как устроен мир

`src/features/terrain/worldGeneration.ts` содержит детерминированную функцию `heightAt(x,z)` с шумом и волнами барханов. Мир разбит на чанки 96×96 метров. Вокруг игрока поддерживается сетка с тремя уровнями детализации: 25×25 видимых чанков и дополнительное кольцо предзагрузки, всего 27×27. План обновляется при пересечении границы чанка. Мелкая рябь и песчинки передаются картой нормалей и текстурой цвета песка с mip-уровнями для дали. Поскольку высота вычисляется по мировым координатам, края чанков совпадают.

## Ограничения первой версии

- Требуется десктопный браузер с WebGL2 и клавиатура с мышью.
- Физика упрощена: камни и стволы пальм имеют неподвижные прямоугольные коллайдеры. Можно скользить вдоль препятствий, перепрыгивать низкие камни и приземляться на них. Плавание упрощённое, камни неподвижны.
- Рельеф загружается постепенно после открытия страницы; декорации оазисов пока создаются в основном потоке.
- Есть инвентарь, потребности, выносливость, температура, состояния организма и стартовый лагерь. Одежда, переносной навес и костёр активны; потеря сознания и смерть ещё не реализованы. Сохранение локальное, привязано к браузеру и адресу игры.

## Смена дня и ночи

Полный цикл занимает 48 реальных минут: по 24 минуты дня и ночи. Новая сессия начинается в 08:00; время сохраняется вместе с припасами. В меню, инвентаре, крафте, открытом ящике и скрытой вкладке игровое время и потребности стоят на паузе; офлайн-расхода нет. Длительность задана в `src/features/environment/dayCycle.ts` константами `DAY_SECONDS` и `NIGHT_SECONDS`.

В правом верхнем углу HUD отображается игровое время **ЧЧ:ММ** из той же фазы, что движение солнца и луны: рассвет — 06:00, полдень — 12:00, заход — 18:00, полночь — 00:00. Небо и горный горизонт используют общее сохранённое время. Обновление часов отправляется только при смене игровой минуты.

В блоке **Дебаг → Время суток** доступны **Обычный цикл**, **День**, **Ночь** и **Закат**. По умолчанию включён обычный цикл. Фиксированные режимы задают освещение и часы 12:00 / 00:00 / 16:12; закат держит солнце примерно в 13° над горизонтом. Температура воздуха и солнечный нагрев соответствуют выбранному режиму. Внутреннее время и потребности продолжают идти во время игры, поэтому фиксированная ночь сохраняет холодные условия, а день — дневные. Возврат к обычному циклу показывает текущую сохранённую фазу. Выбор режима действует до перезагрузки.

## Ландшафт и оазисы

Пустыня состоит из извилистых дюнных гряд, широких междюнных понижений и более спокойных песчаных участков. Основные гряды имеют шаг около 410 метров, вторичные дюны — около 135 метров. Гребни стали острее: гладкие основания соединяются на выраженном перегибе, наветренный склон занимает 72% профиля. Наветренные склоны длиннее подветренных; высота гряд и их выраженность меняются по миру. Каменистые возвышенности остаются редкими. Вдали от оазисов иногда встречаются сухие ветвистые деревья разной высоты с коллизиями. В каждой области 384×384 метра есть 14% шанс появления оазиса: озеро с асимметричными берегами в углублении, пятна зелени, пучки травы и неравномерные группы пальм высотой 3–12 метров. Камни собраны в небольшие группы у берегов оазисов и изредка у сухих деревьев; случайная россыпь по открытым дюнам удалена. Каждый камень принадлежит одному чанку, включая группы на стыках; визуализация и коллизии используют общие данные. Развалин пока нет. Генерация детерминирована, поэтому найденные места сохраняются при возвращении. Ближайший к старту оазис расположен примерно в X=−968, Z=−168.

Геометрия и анимация пальмовых листьев находятся в `features/vegetation/palmFronds.ts`. Изгиб ограничен 0,9 м в локальной геометрии, основания листьев остаются на кроне. Границы геометрии заранее расширены на максимальный изгиб, чтобы отсечение по камере учитывало ветер. Оазисы используют общие геометрию и материал листвы: ими владеет `Oases`, а при выгрузке отдельного оазиса React Three Fiber освобождает его инстансированные буферы.

Коллизии используют те же данные генерации, что и видимые объекты. Движение разбивается на короткие шаги, чтобы игрок не проходил сквозь тонкие стволы на бегу. Проверки мира и коллизий: `npm test`.

## Ветер

`src/features/environment/wind.ts` задаёт общее поле ветра в метрах в секунду: постоянное направление к +X/+Z (0,8 радиана от оси +X, константа `WIND_DIRECTION`) и плавные порывы силы, проходящие через мир по ветру. Поле управляет изгибом травы, колебаниями листьев пальм и движением перекати-поля. Скорость ветра показана в интерфейсе в км/ч. Буря усиливает скорость, сохраняя направление. Частицы пыли переносятся по тому же вектору без вертикального дрейфа; движение экранного зерна проецируется из мирового ветра в текущий вид камеры.

Перекати-поле имеет радиус 0,225–0,45 метра и появляется редко (первые несколько секунд, затем попытка каждые 22–47 секунд), одновременно активно не больше трёх. Оно разгоняется по ветру, учитывает уклон, катится с вращением и простыми коллизиями, не заезжает в озёра.

### Пылевая буря и дебаг

На главном экране и в меню паузы есть блок **Дебаг → Пылевая буря**. Галочка сразу включает или выключает бурю, не начиная игру. По умолчанию она выключена (`DEFAULT_STORM_ENABLED` в `features/environment/stormWeather.ts`); остаток сохраняется при перезагрузке. Включённая буря длится 6 игровых часов активной симуляции, в том числе во сне; повторное включение запускает новый срок. Нажмите Esc во время игры, чтобы вернуться к переключателю.

Общее состояние погоды передаётся через `weatherContext.ts`. При выключении выгружаются пылинки, фон бури и экранная зернистость, возвращаются атмосферное небо, светила, звёзды, обычное освещение и дальний туман 300–1080 м. Ветер одновременно возвращается к спокойной силе в HUD, траве, пальмах и перекати-поле. Чистая функция `windAt` получает интенсивность явно, без глобального изменяемого состояния. Включение и выключение не сбрасывают позицию, время суток или стриминг мира. Случайное начало и плавные фазы пока не добавлены; по истечении срока буря выключается автоматически.

При включённой буре туман начинает ослаблять контраст после 5 м и полностью скрывает объекты к 65 м. На 50 м формула тумана оставляет около 16% исходного контраста для дальних силуэтов. Непрозрачность зернистости и пылинок уменьшена, чтобы ближняя земля и объекты оставались читаемыми. Общий ветер усилен в 6 раз (примерно 35–170 км/ч с порывами). Обычный Sky отключён, `StormAtmosphere.tsx` рисует непрозрачный пыльный фон со слабым солнечным ореолом. Широкие размытые полосы удалены: поверх неба и земли движется мелкая зернистость с размером зерна около 1,25 CSS-пикселя с учётом плотности экрана. Она вычисляется по отдельным ячейкам без интерполяции облачного шума; изображение сцены не размывается и не копируется в текстуру. Оттенок пыли меняется днём и ночью.

`DustStorm.tsx` рисует 2400 мелких пылинок одним набором точек в объёме 8×8×8 м вокруг камеры. Размер точки ограничен 3 пикселями. Движение рассчитывается на GPU, в кадре обновляются uniform-параметры. Частицы скрываются за геометрией и исчезают у камеры и по краям локального объёма. Буферы создаются при включении, геометрии и материалы освобождаются React Three Fiber при выключении. Фон и зернистость добавляют два прохода по экрану. Дополнительных текстур, источников света и зависимостей нет; позёмка не возвращена. Дальность стриминга мира сохранена, туман сам по себе не сокращает память кеша.

Тесты проверяют возврат спокойного ветра и повторное включение в переиспользуемом буфере без накопления усиления. Визуальную проверку пользователь выполняет сам; собственная визуальная проверка и замеры FPS не выполнены.

### Рябь песка


Рябь песка мелкая, с небольшим рельефом. Её сила задаётся уклоном поверхности и неоднородными пятнами в мировых координатах: на ровной земле остаётся почти гладкий зернистый песок, на склонах чередуются участки ряби и гладкого песка.

### Референсы рельефа

Формы ориентированы на длинные дюнные гряды и междюнные понижения, описанные и показанные в [NPS: Dune Types](https://www.nps.gov/grsa/learn/nature/dune-types.htm) и [NASA: Sandscapes of the Namib Desert](https://science.nasa.gov/earth/earth-observatory/sandscapes-of-the-namib-desert-146138/). Генерация художественная, не физическая симуляция образования дюн. На тестовой области 3,2×3,2 км перепад высот составляет примерно 86 метров, в радиусе 600 метров от старта — 47 метров.

## Первый этап приближения к референсу пустыни

При реализации этого визуального этапа использовались ясная погода и фиксированный **Закат**. Теперь по умолчанию активен обычный цикл; закат и буря доступны в дебаге. Это первый визуальный этап, а не подтверждение фотореализма.

`features/environment/MountainHorizon.tsx` отображает три замкнутых слоя гор на условных расстояниях 3,6, 5,2 и 7,4 км; их силуэты детерминированно создаёт `mountainGeometry.ts`. Нижние части переходят в цвет дымки, дальние слои имеют меньший контраст; цвета меняются днём и ночью. Это декоративный горизонт, который следует за камерой: до гор нельзя дойти. При включении бури слои размонтируются и их ресурсы освобождаются. В спокойную погоду это три дополнительных меша, всего около 3000 треугольников, без текстур, коллизий и генерации новых мировых чанков.

Солнечные тени расширены на область 360×360 м; тени отбрасывают только ближайшие 5×5 чанков рельефа, флаги обновляются при смене области даже до готовности нового LOD. В теневом проходе участвует только поверхность чанка: вертикальные полосы, закрывающие щели LOD, видимы в основном проходе, но не отбрасывают сетку теней по границам. Размер карты теней сохранён 2048×2048, дополнительных источников света нет. Стоимость теневого прохода возрастает; замеры FPS не выполнены. За пределами ближайшей области тени от дюн пока не рассчитываются.

Профиль дюн изменён в общей функции высоты, используемой генерацией и физикой. Поэтому высоты и зависящая от них растительность отличаются от прошлой версии; старые сохранения не удаляются, игрок приводится к поверхности существующей физикой. Рябь песка немного усилена вблизи и затухает на дистанции 18–95 м, крупная пятнистость цвета уменьшена. Дальность стриминга и количество LOD не увеличены.

Визуальную проверку пользователь выполняет сам; собственная проверка картинки, шейдеров на GPU и замеры FPS не выполнялись.

## Движение в воде

На мелководье скорость плавно снижается с глубиной погружения. В глубокой воде игрок автоматически держится у поверхности, глаза остаются на 38 см выше воды. Скорость плавания — до 2,4 м/с, Shift её не увеличивает; перегруз дополнительно снижает скорость. На мелководье возможен ослабленный прыжок при достаточной выносливости, при плавании прыжок отключён. На берег игрок выходит обычным движением WASD. Погружения и запаса воздуха пока нет.

## Небо и FPS

Панель показывает FPS, усреднённый за полсекунды по реальному времени кадров. Длинные промежутки после возвращения на вкладку отбрасываются. Солнце и луна рисуются отдельными дисками без тумана; 900 звёзд — одним набором точек. Атмосфера рисуется шейдером неба. Дополнительных лунных теней нет. Траектория наклонена: в середине дня и ночи светило видно примерно на 30° выше горизонта в направлении начального взгляда.

## Потоковая загрузка рельефа

`chunkGeometry.ts` создаёт итоговые типизированные буферы без промежуточной геометрии. Два фоновых потока `terrain.worker.ts` рассчитывают их и передают через transferable buffers. Высоты и коллизии используют общую функцию мира из `worldGeneration.ts`.

`terrainPlan.ts` задаёт приоритет от ближайших участков к дальним, дополнительное кольцо предзагрузки и гистерезис LOD в один чанк. `TerrainStream.ts` управляет очередью, заменой геометрии и LRU-кешем: до 900 геометрий и 64 МиБ буферов, с защитой геометрий, которые ещё отображаются. При смене LOD старая геометрия остаётся до готовности новой. Устаревшие ответы фоновых потоков отбрасываются.

За кадр подключается максимум две геометрии при бюджете обработки 2 мс. Это ограничивает число новых GPU-загрузок, но не гарантирует жёсткий предел времени самого GPU-драйвера. Завершённые фоновые задачи имеют ограниченную очередь. При размонтировании потоки завершаются, геометрии и материалы освобождаются. Ошибки загрузки выводятся в интерфейсе.

`npm test` проверяет передачу данных из отдельного потока, стыки LOD, приоритеты, удержание старой геометрии, повторное использование кеша и устаревшие ответы. Реальные задержки кадров и работу Web Workers в браузере нужно проверять отдельно.

## Возвращение в исследованные места

Позиция и направление взгляда сохраняются в `localStorage` каждые 3 секунды во время игры, при скрытии страницы и уходе с неё. При следующем запуске игрок и очередь рельефа начинают с сохранённого места. Повреждённые записи игнорируются; недоступность хранилища не ломает игру.

Статичные объекты имеют устойчивые идентификаторы вида `тип:область:номер` в `features/terrain/objectIndex.ts`. Отображение и коллизии используют общие индексированные данные. Индекс ограничен: по 512 областей для камней и сухих деревьев, по 128 для пальм и травы. После вытеснения данные восстанавливаются той же генерацией по координатам. Модель и версия генерации должны оставаться прежними для сохранения расположения объектов; геометрия всего исследованного мира на диск не записывается.

Подгружается ближайшее окружение; коллизии рассчитываются по соседним областям, а не по всему миру. Время суток сохраняется с припасами; перекати-поле и ветер между запусками не сохраняются. Камни и растительность остаются неизменяемыми; отдельная категория подбираемых предметов описана ниже.

## Исследование: записки, старая дорога и деревушки

В ящиках одиночных караванов и жилищ изредка встречаются бумажные заметки: шанс 30% до проверки расстояния. В деревушках и ближе 250 м к любому их дому записки не генерируются. На карточке «Заметки» нажмите «Читать»: откроется отдельное окно. Читать можно прямо в ящике, даже если нет свободного слота; записку можно забрать, перечитывать в припасах, выбросить и хранить в своём ящике. Все записки занимают одну группу инвентаря, каждый лист весит 0,01 кг. Действия переноса сохраняются сразу. Записка остаётся содержимым ящика и должна быть забрана перед его разборкой.

Указания рассчитаны от исходного ящика: название поселения, сторона света и примерное расстояние до настоящих домов, при наличии — до каменных ворот и от них до домов. Направления относятся к месту находки, а не к текущему положению после переноса записки. В деревушках записок нет; зацепки ищут на удалении от них. Чтение не раскрывает карту и не создаёт указатель задания; названные места можно найти и самостоятельно.

Подобранную записку можно разобрать в окне чтения из припасов: один экземпляр превращается в один лист бумаги, текст утрачивается. Замена атомарна: при нехватке слота записка остаётся целой. Бумага весит 0,01 кг, складывается в стеки до четырёх листов и использует общий слот своего типа. Её можно хранить, оставлять и подбирать. В окне костра один лист добавляет ровно 10 игровых минут топлива; доска по-прежнему даёт 2 часа. Запас не превышает 8 часов, при переполнении лист не расходуется. Бумага не зажигает потушенный костёр автоматически. Остаток топлива показан в часах и минутах. Уже подобранные записки старых сохранений сохраняются, в том числе найденные прежде в деревнях. Целевые проверки — `node tests/paper.mjs`.

Добавлены заброшенные деревушки из 3–5 разнесённых глинобитных домов, ящики с существующими припасами и высокие остатки каменных ворот у дороги. Участки с неподходящим рельефом, водой или природными препятствиями отбраковываются; если не удаётся разместить минимум три дома, деревушка отсутствует и записки не направляют к ней. Первое поселение есть к юго-востоку от стартовой области; записка в раннем караване теперь не гарантирована. Дорога идёт с запада на восток, повторяется редкими полосами, изгибается по существующему рельефу и прерывается песчаными наносами и водой. Это остатки дорожного полотна, без изменения высот земли и дополнительного препятствия для ходьбы.

Деревушка и каменные ворота отмечаются на карте после подхода, название деревушки видно в подписи значка. Новая генерация отделена от прежних жилищ, караванов и постов: их координаты и прежние ID лута сохранены. Схема 19 хранит записки, открытия и разобранные ящики; прежние версии не загружаются. Уже разобранные старые ящики не возвращаются ради заметок. Уникальные предметы, новые рецепты и опасности на этом шаге не добавлены.

Генерация, описания маршрутов и дорожная геометрия находятся в `features/exploration`, окно чтения — в `ui/exploration`. Статические части инстансированы через общий рендер конструкций; дорога собирается при смене чанка, ресурсы принадлежат React Three Fiber, кеш регионов ограничен. Новых покадровых расчётов и источников света нет. Проверка — `node tests/exploration.mjs` и синтаксическая транспиляция затронутых файлов. Общие прогоны, браузер, собственная визуальная проверка и замеры FPS не выполнялись.

## Полевой крафт и переносной навес

В ящиках локаций находятся ткань и верёвка: жилище — 4 ткани, караван — 2 верёвки, пост — 2 ткани и 1 верёвка. Древесина не генерируется отдельной находкой или содержимым ящика: **доски получают только разборкой пустых ящиков, по 4 за ящик**. Жерди как отдельный тип удалены. Одна доска весит 0,5 кг, ткань — 0,2 кг, верёвка — 0,15 кг. Внутренние стеки до четырёх; все экземпляры одного типа занимают один групповой слот. Прежние ID других припасов и позиции локаций сохранены.

В отдельном окне «Крафт» (C или кнопка «Крафт» в инвентаре) доступен первый рецепт: **4 ткани + 2 верёвки + 8 досок → переносной навес, 5,1 кг**. Показываются имеющиеся и недостающие материалы. Изготовление расходует компоненты сразу из нескольких стеков и выдаёт один комплект; при нехватке материалов или места операция целиком отменяется.

Окно крафта имеет три колонки: слева список доступных рецептов, посередине поворачиваемый предпросмотр результата с размером и весом, справа материалы «с собой / нужно», причина недоступности и кнопка «Изготовить». Доступны рецепты навеса, ящика, костра и кровати; выбор в левом списке меняет предпросмотр, состав и действие изготовления. Предпросмотр построен из той же геометрии навеса или ящика, что в мире, на ровной поверхности: его можно вращать перетаскиванием мышью/пальцем или кнопками. Предпросмотр использует те же GLB в отдельном Canvas с frameloop="demand": кадры обновляются при загрузке, смене рецепта, вращении и изменении размера. На узких экранах колонки располагаются вертикально, окно прокручивается в пределах высоты экрана.

C и крестик × закрывают крафт с возвратом в игру; I или кнопка «Припасы» переключают к инвентарю, M — к найденной карте, Escape — к меню паузы. Во время просмотра и переключения окон симуляция стоит на паузе. После изготовления комплект находится в припасах, откуда доступно размещение. Сворачивание установленных навесов остаётся в инвентаре. Инвентарь, карта, крафт и ящик используют одно состояние открытого окна и не показываются одновременно.

На карточке готового комплекта нажмите «Разместить». Игра возобновится: перед игроком появится зелёный или красный предпросмотр. E подтверждает установку с повторной проверкой места, Q отменяет без расхода комплекта. Пауза, открытие других окон и скрытие вкладки также отменяют размещение. Навес ориентирован по осям мира; под крышу можно зайти с любой из четырёх сторон, поворот пока не предусмотрен.

Размер навеса — 4×3 м, высота — 3,2 м, горизонтальная тканевая крыша на четырёх вертикальных стойках, без стен. Установка доступна с сухой земли на расстоянии около 4,5 м: проверяется участок с запасом 0,6 м, вода, перепад высот не более 0,6 м, постройки/растения и другие навесы. Нельзя поставить навес на себя, в воздухе или внутри существующей постройки. Стойки заглубляются в рельеф; выравнивания дюн нет. Лимит сохранения — 128 установленных навесов.

Геометрия навеса определяет коллизии четырёх стоек и крыши, а также игровую тень независимо от графических теней. Внутри действует та же модель защиты от ветра и постепенной нормализации температуры, что в стартовом лагере; вода и еда продолжают расходоваться, накопленные состояния восстанавливаются постепенно. Навес не имеет отдельного источника тепла или топлива. В инвентаре в пределах 4 м появляется кнопка «Свернуть навес»: возвращается целый комплект с тем же ID, без возврата отдельных материалов. При нехватке места/веса навес остаётся установленным.

Схема сохранения **19** по прежнему ключу `desert-walker.survival.v1` сохраняет установленные навесы и счётчик изготовленных комплектов. Изготовление, установка и сворачивание сохраняются сразу. После ухода и перезапуска навесы восстанавливаются. Установленные навесы используют открытую форму; позиции и ID сохраняются в текущем формате. Отображение ограничено ближайшими 5×5 чанками, объединённые коллайдеры кешируются по чанкам и сбрасываются при установке/сворачивании. Геометрией и материалами владеет React Three Fiber.

`tests/camps.mjs` включён в `npm test`: расход и остатки материалов, ограничения массы/слотов, подбор/выбрасывание комплекта, размещение на реальном рельефе, вход и выход со всех четырёх сторон, коллизии стоек и потолка, тепловая защита, отсутствие дублирования, сохранение при возвращении/перезапуске. Внешний вид, удобство размещения, баланс экспедиции, FPS и память в браузере не проверялись.

Солнечная карта теней следует за игроком с привязкой к целым пикселям в координатах световой камеры (`features/environment/shadowTracking.ts`), чтобы движение не сдвигало сетку выборки теней на доли пикселя. Разрешение остаётся 2048×2048, область — 360×360 м. У ящика корпус заканчивается под крышкой, без совпадающих наружных верхних граней. Эти изменения проверены точечными расчётами; отсутствие мерцания в игре и FPS отдельно не подтверждены.

Материал крафта — доски; прежние жерди и прежняя масса навеса не мигрируются. Комплекты навеса весят 5,1 кг. Проверки текущих рецептов и материалов — `tests/wood.mjs`, включён в общий `npm test`.

## Разборка одежды

У снятого головного убора и тёплой одежды в припасах есть действие «Разобрать → ткань». Головной убор даёт **1 ткань**, тёплая одежда — **4 ткани**. Это тот же материал, который нужен для навеса и костра; отдельный тип тряпок не вводится. Надетую вещь сначала нужно снять.

Разбирается один экземпляр. После удаления исходной вещи проверяются масса и групповые слоты результата; если ткань не помещается, операция целиком отменяется. Ткань дополняет существующие стеки до четырёх, одинаковые типы занимают один слот. Результат сохраняется сразу по схеме 13; повторная разборка того же экземпляра не выдаёт ткань снова.

## Костёр

В крафте (C) доступен **«Костёр»: 2 доски + 1 ткань → комплект массой 1,2 кг**. Разместите комплект из припасов: E подтверждает место, Q отменяет. Нужна сухая достаточно ровная земля и свободное пространство вокруг; ставить костёр в воду, на себя, вплотную к вещам или поверх другого костра нельзя. Размещённое кострище сначала не горит.

Посмотрите на костёр и нажмите E. В отдельном окне доступны «Разжечь», «Потушить», добавление доски и удаление потушенного кострища без возврата материалов. Воспламенитель в этой версии не требуется. Начального топлива хватает на 4 игровых часа (8 реальных минут); одна доска добавляет 2 игровых часа, предел — 8 игровых часов. Сгорание учитывается только при активной симуляции; в обычных окнах, меню, скрытой вкладке и вне игры топливо не расходуется. Во время сна топливо расходуется вместе с ускоренным игровым временем. При исчерпании запаса огонь гаснет. Тушение сохраняет остаток топлива.

Горящий костёр добавляет тепло в пределах 4 м с ослаблением по расстоянию; стены и другие препятствия перекрывают тепло. Остаток топлива учитывается в последнем неполном шаге горения. Влияние идёт через существующую инерционную температуру тела и накопленные состояния: огонь не лечит мгновенно. Существующая температурная защита навесов сохранена; тепло костра добавляется после её расчёта, поэтому в жаре и укрытии можно перегреться. Тепло нескольких костров не складывается, учитывается самое сильное доступное.

Поленья и анимированное пламя отображаются около игрока инстансами; для освещения используются максимум два ближайших источника без теней. Анимация огня приостанавливается вместе с игрой. Геометрия поленьев общая для мира, размещения и предпросмотра крафта. Изменения топлива не пересоздают статическую геометрию и кеш коллизий. Лимит — 32 костра. Графикой и ресурсами владеет React Three Fiber.

Схема **19** сохраняет позиции, горение, остаток топлива и счётчик комплектов по прежнему ключу. Действия сохраняются сразу; расход топлива — по интервалу сохранения симуляции. `tests/fire.mjs` включён в `npm test`; общий набор тестов, проверка TypeScript и сборка проходят. Браузер, графика, баланс прохождением и FPS не проверялись.

## Кровать и сон

В окне крафта C доступна кровать: 4 доски + 4 ткани + 2 верёвки, комплект 3,1 кг. Разместите её из припасов I на свободной сухой земле, затем подойдите и нажмите E. В окне кровати выбирается от 1 до 12 игровых часов; кнопка «Лечь и уснуть» запускает ускоренную симуляцию, камера опускается на кровать. Можно проснуться кнопкой, закрытием окна или Escape.

Сон продвигает время суток, погоду, расход воды, еды и топлива, рассчитывает температуру и состояния организма. В безопасной тени при нормальной температуре накопленные недомогания проходят постепенно: не более 8 процентных пунктов тяжести каждого состояния за игровой час, при выполнении обычных условий восстановления. Отдельной шкалы HP нет. Сон на солнце не лечит; опасная жажда, голод, жара или холод будят раньше выбранного срока. Перед долгим сном нужны припасы и подходящее укрытие. Включённую бурю можно переждать, если условия позволяют спать достаточно долго.

Схема 19 сохраняет кровати и оставшееся время бури. Пройденная часть сна сохраняется, но сам сеанс сна после загрузки не продолжается; скрытие вкладки и уход со страницы будят персонажа. Офлайн-прогресса нет. Расчёты сна выполняются ограниченными порциями, статические кровати и коллизии не перестраиваются при каждом шаге времени.

Проверка механики — `node tests/sleep.mjs`. Общие тесты и сборка не запускались по просьбе пользователя. Собственная визуальная проверка и замеры FPS не выполнялись.

## Разборка ящиков и своё хранилище

При разработке App пересоздаёт объект игры при горячем обновлении правил, чтобы новая сцена не использовала старую логику поиска ящиков. Если окно не может разрешить ID ящика, оно показывает «Ящик недоступен», а не ложное «Пусто». После обновления кода уже открытую вкладку можно перезагрузить без удаления сохранения.

Опустошите найденный ящик и нажмите «Разобрать». Разборка даёт **4 доски** по 0,5 кг и удаляет ящик из отображения, взаимодействия и коллизий. Пока в нём есть вещи, разборка недоступна. Если доски не помещаются в припасы, операция отменяется целиком. Стартовый ящик тоже можно разобрать после извлечения доступного содержимого.

В крафте (C) выберите **«Ящик»**: 4 доски → комплект ящика, 2 кг. На карточке комплекта в припасах нажмите «Разместить»: E устанавливает его, Q отменяет. Проверяются сухая земля, уклон и свободное место. Крыша навеса не мешает установить ящик под ней; стойки, другие ящики и препятствия мешают. Размер корпуса — 1,25×0,85×0,7 м.

Свой ящик открывается через E. Слева его содержимое с действием «Забрать», справа припасы с действием «Положить». Переносится один экземпляр или исходный стек целиком; одинаковые типы занимают один групповой слот. Вместимость — 12 типов вещей и 60 кг. При нехватке вместимости ни одна сторона не меняется. Наполнение фляг, ID вещей и стеки сохраняются. Пустой свой ящик также разбирается в 4 доски.

Схема 19 сохраняет удалённые процедурные ящики, свои размещённые ящики, их содержимое и счётчик комплектов по прежнему ключу. Все действия сохраняются сразу; после ухода и перезапуска изменения восстанавливаются. Проверяется уникальность ID между припасами, экипировкой, землёй, навесами и хранилищами. Лимиты — 128 своих ящиков и 10 000 разобранных процедурных ящиков.

`features/storage` хранит модель и действия, `features/placement` — общий предпросмотр и кеш изменяемых коллизий. Общие данные конструкции ящика используются в мире, при размещении и в крафте. `tests/storage.mjs` проверяет разборку/изготовление/установку под навесом, сохранение содержимого, отсутствие дублирования, ограничения и отказ хранилища. Собственная визуальная проверка и замеры FPS не выполнялись.

## Припасы и первые потребности

Активен стартовый инвентарь: 5 слотов и рекомендуемый груз 5 кг, фляга на 1 л и два сухпайка в одном стеке. Полная фляга весит 1,2 кг, пустая — 0,2 кг; один сухпаёк — 0,4 кг. Сухпайки складываются по четыре в слот. Простой рюкзак весит 0,6 кг и после надевания даёт 12 слотов и рекомендуемый груз 20 кг; его масса входит в общий вес, сам надетый рюкзак слот не занимает. Допускается перегруз до 150%: предельный вес без рюкзака — 7,5 кг, с рюкзаком — 30 кг. Выше рекомендованного веса скорость плавно снижается, до 60% при предельном перегрузе. При дальнейшем увеличении веса подбор запрещён. Для снятия рюкзака вещи вместе с ним должны помещаться в обычные пять слотов и 7,5 кг.

Полезный лут находится у трёх типов небольших локаций: заброшенное жилище с остатком крыши, караван с брошенной повозкой и флагом, исследовательский пост с десятиметровой антенной. Жилища содержат в основном сухпайки, иногда головной убор; караваны — запечатанную питьевую воду и немного еды; посты — воду, еду и иногда тёплую одежду. Это начальная версия локаций из простых форм, без ремонта и навигационных приборов. Находки находятся в ящиках; E открывает содержимое, подсказка указывает тип локации.

Локации детерминированы. Для жилища задан ранний кандидат в чанке (0, −1), для каравана — (1, 0), для поста — (−1, −1): ориентировочно 70–170 м от старта в зависимости от выбранного места. В остальных чанках сначала проверяется вероятность 10%, затем до 24 мест на сухой поверхности с перепадом до 1,2 м на участке 14×14 м, вне камней и деревьев. Если подходящего места нет, локация не создаётся, в том числе у ранних кандидатов. Рельеф не выравнивается. Постройки погружены относительно земли в центре участка на стабильную для каждой локации глубину: жилища на 0,2–0,65 м, караваны на 0,45–1,15 м, посты на 0,15–0,5 м. На склоне разные части естественно скрываются песком на разную высоту; колёса и нижняя часть повозок могут почти полностью исчезать. Геометрия и коллизии опускаются вместе. Высота некоторых занесённых входов уменьшается; ящики вынесены к доступной стороне (+Z) на 4 м от центра локации. Стены, крыши и вышки используют одни и те же коробки в изображении, коллизиях и расчёте игровой тени. Нормализацию температуры дают стартовый лагерь и установленные переносные навесы; другие постройки дают игровую тень по своей геометрии. Проверка маршрутов и частоты находок в игре ещё не выполнена.

Одинаковые наборы припасов посреди пустыни удалены. В стартовом ящике (X=0, Z=−7) находятся еда, одежда и единственный генерируемый рюкзак. Если рюкзак уже найден, в том числе в прежней версии игры, стартовый рюкзак больше не предлагается; это определяется по экипировке, инвентарю, оставленным вещам и сохранённым ID подборов. Новые фляги в мире не генерируются: одна полная фляга есть в стартовом инвентаре, её можно пополнять у оазисов. Уже имеющиеся и оставленные рюкзаки/фляги сохранены и доступны для повторного подбора. Сохранённая позиция игрока не переносится к новым локациям. Янтарные осколки остаются временно скрытым отдельным прототипом.

В текущей схеме сохранения 13 содержимое ящиков восстанавливается по прежним ID предметов и списку подборов. Уже взятые вещи не возвращаются после переноса в ящики или перезапуска; инвентарь и оставленные вещи сохраняются. Отдельное состояние открытой крышки не сохраняется: открытие — панель осмотра, а не анимация.

Пакеты питьевой воды — расходник, по 0,25 л и 0,27 кг, стеки до четырёх. Один пакет восстанавливает до 40 воды организма и расходуется целиком; пустая тара не остаётся. В инвентаре нажмите «Пить» у пакета; R сначала использует воду фляги, затем пакеты, если во флягах воды нет. Пакеты учитываются в общем запасе воды HUD, весе, подборе, оставлении и сохранении. В отличие от фляг они не наполняются повторно.

Чтобы обыскать ящик, посмотрите на его крышку в пределах 3 м и нажмите E. Откроется панель с названиями, количеством и весом находок; кнопка «Забрать» переносит выбранный предмет/стек. Сухпайки и пакеты воды дополняют соответствующие стеки до четырёх. При нехватке слотов или допустимого веса перенос недоступен с объяснением; вещь остаётся в ящике. Во время просмотра действует пауза. Крестик × возвращает управление мышью, I открывает припасы, Escape — меню паузы. В окне убраны название локации, надпись о паузе, длинный счётчик груза, подсказки клавиш и поясняющий абзац; остаются карточки, действия и необходимые причины недоступности. Пустой ящик можно разобрать.

Все генерируемые находки, включая стартовые, теперь находятся в ящиках; отдельными объектами на земле отображаются только вещи, оставленные игроком. Для их повторного подбора посмотрите на предмет и нажмите E. Стены, камни, стволы и сами ящики блокируют взаимодействие сквозь них. Ближайшая доступная цель перед игроком имеет приоритет перед наполнением фляг.

Объём воды и вес указаны одной строкой карточки, подробности ёмкости и упаковки — ниже. Личный инвентарь (I) имеет компактное окно шириной до 720 px с уменьшенными карточками, иконками 44 px и внутренней прокруткой по высоте экрана. Окна ящиков и крафта сохраняют отдельные размеры. Инвентарь отображается адаптивной сеткой карточек: у каждого типа предмета своя иконка с подписью, у стеков показано количество, у фляги — остаток воды; ниже указаны описание, вес и доступные действия. Пустые слоты тоже видны: 5 без рюкзака и 12 с надетым рюкзаком. Экипировка вынесена в отдельную сетку с отметкой «Надето» и кнопкой «Снять». Содержимое ящиков использует те же карточки с кнопкой «Забрать» и объяснением ограничений вместимости. Одинаковые типы предметов сгруппированы в одну карточку с общим количеством и суммарным весом; у фляг показан суммарный запас и ёмкость воды. Группировка действует также в ящиках. Каждая группа одинакового типа занимает один слот независимо от числа вещей и внутренних стеков. Счётчик вместимости, свободные карточки, подбор, снятие экипировки и проверка сохранений используют это правило. Масса всех вещей складывается по-прежнему; внутренние стеки до четырёх и отдельные экземпляры фляг с собственным наполнением сохраняются для действий и сохранений. «Выбросить» переносит одну вещь или один исходный стек, количество указано на кнопке; «Забрать» работает так же и выбирает доступный по вместимости стек. Питьё и еда расходуют одну порцию, экипировка — один предмет. В панели есть предметы, экипировка, вместимость, вес, кнопка перехода в отдельное окно крафта и сворачивание расположенных рядом навесов. Сведения об организме и игровые подсказки из инвентаря убраны; игровой HUD скрывается при открытом инвентаре или ящике.

Кнопка «Выбросить» в инвентаре переносит предмет или целый стек на землю рядом с игроком. Нужна сухая опора; в прыжке, на воде или у неподходящего края операция отклоняется. Вещи располагаются вокруг игрока, подбираются повторно и сохраняются при уходе из области и перезапуске. Надетые вещи перед оставлением нужно снять. Перекладывание своих вещей в ящики пока не реализовано.

Вода организма и сытость лежат в диапазоне 0–100. За игровой час базово расходуется 5 единиц воды и 2 еды; при беге — 12 и 3 с учётом фактической доли бега в периоде. Перегрев дополнительно повышает расход воды. Физика передаёт реальное движение и режим бега: стояние с Shift, упор в препятствие и плавание не считаются бегом. Перегруженный бег учитывается даже при сниженной скорости. Четверть литра восстанавливает до 40 единиц воды; при небольшом дефиците расходуется только необходимая часть. Сухпаёк восстанавливает до 35 единиц сытости. При значении 25 и ниже появляются предупреждения; вода или сытость 5 и ниже блокируют бег. Полоски HP нет.

Выносливость отображается в HUD и инвентаре. Бег расходует базовые 10 единиц за реальную секунду, подъём — 5 за метр набранной высоты, прыжок — 12 за действие; груз повышает затраты. После нагрузки действует задержка восстановления 1,5 секунды. На ровном месте в покое базовое восстановление — 12 единиц/с, при ходьбе — 6; груз, низкие запасы воды/еды и накопленные состояния организма замедляют его. При сытости ниже 25 базовый максимум уменьшается со 100 до 60; истощение и температурные состояния дополнительно снижают доступный запас. Еда не устраняет накопленную слабость мгновенно. После полного утомления бег возобновляется при восстановлении 25% доступного запаса. Тяжёлые и критические состояния блокируют бег независимо от выносливости. Прыжок отклоняется при нехватке сил. Числа предварительные, прохождением пока не настроены.

Выносливость и задержка восстановления стоят на паузе вместе с потребностями. Физика движения и прыжка также приостанавливается в меню и скрытой вкладке. Декоративные анимации окружения продолжают работать.

Задержку восстановления заново запускают бег и прыжки. Обычная ходьба в гору не сбрасывает её: после завершения задержки силы восстанавливаются за вычетом затрат на набор высоты. На крутом подъёме или с тяжёлым грузом расход может превышать восстановление; остановка убирает затраты на движение. Инвентарь и меню являются паузой, а не отдыхом с течением времени.

Вода оазисов сейчас считается питьевой. Подсказка E появляется, когда реальная водная поверхность доступна в пределах 2,5 м от глаз; проверка учитывает вертикальную дистанцию и позволяет пополнять фляги с сухого берега. Издалека и с высоких уступов взаимодействие недоступно. Наполнение учитывает доступный вес: при недостатке вместимости фляги заполняются частично, причина выводится в HUD.

`features/survival` хранит время, потребности и инвентарь одной записью `desert-walker.survival.v1` в localStorage. Симуляция обновляется примерно четыре раза в секунду, сохранение — каждые три активные секунды, после использования предмета/набора воды, при паузе и уходе со страницы. В инвентаре можно использовать предметы во время паузы. Повреждённые/несовместимые данные блокируют запуск и запись до явного выбора новой игры с резервной копией; отказ хранилища оставляет прогресс в памяти и допускает повторную запись. Существующие сохранения позиции и осколков не удаляются. Пауза не останавливает декоративный ветер и частицы.

Текущая схема записи — версия 19 по прежнему ключу. Сохраняются экипировка, находки, оставленные вещи, потребности и состояния организма, время/погода, карта/открытия, контейнеры, сооружения и группы с состояниями деталей и соединений. Версии 1–18 не загружаются и не мигрируются. Экран несовместимого сохранения позволяет экспортировать исходный JSON и явно начать новую игру с резервной копией. Подробности — [GAMEOBJECT_ARCHITECTURE.md](GAMEOBJECT_ARCHITECTURE.md).

Инвентарь, ящики, карта и крафт закрываются крестиком × в правом верхнем углу окна с возвратом в игру. Прежние нижние кнопки закрытия убраны. При открытии окна фокус устанавливается на крестик без прокрутки; кнопка доступна с клавиатуры и имеет текстовое имя для экранных дикторов.

## Показатели выживания в HUD

С игрового экрана убраны название DESERT, подпись прототипа, надпись «Процедурный мир» и нижний текст о генерации мира. Время и ветер расположены над компасом справа внизу; скорость и FPS — одной строкой под ним. Размер цифр соответствует показателям организма (18 px, на узком экране 15 px), подписи и единицы меньше. Прежние отдельные часы вверху и показатели внизу слева удалены.

Сверху левого столбика расположен крестик состояния организма: зелёный — здоров, жёлтый — лёгкая степень, оранжевый — тяжёлая, красный — критическая. При сочетании состояний цвет определяется самой тяжёлой степенью; при наведении перечислены текущие состояния. Индикатор использует уже накопленные состояния организма, отдельной шкалы HP нет.

Посередине левого края вертикально показаны голубая капля и текущий уровень воды организма, иконка еды и сытость, одна температурная полоска без цифр: синий холод слева, оранжевый перегрев справа, светлый ползунок в нормальном состоянии посередине. Положение ползунка определяется текущей температурой тела: середина соответствует +37 °C, левый край — порогу переохлаждения +36 °C, правый — порогу перегрева +37,7 °C. Ползунок показывает нагрев и охлаждение ещё до накопления болезненных состояний; за пределами этих порогов остаётся у соответствующего края. Крестик здоровья отдельно отражает накопленную тяжесть состояний, поэтому после охлаждения ползунок может вернуться в норму раньше крестика. Градусы воздуха из HUD убраны. Максимальные значения рядом не выводятся. Внизу по центру находятся значок выносливости, полоска доступного запаса и текущее значение без максимума.

Общий запас воды в вещах, масса груза и слоты в HUD не дублируются — они доступны в инвентаре. Предупреждения об опасных состояниях, результат действий и подсказка E расположены отдельно над выносливостью. Сообщение «здоров» в обычном состоянии не показывается. В инвентаре, ящиках и карте эти показатели скрыты вместе с остальным HUD. Индикатор использует существующую температуру тела; влияние накопленного перегрева на расход воды усилено до ×3 при максимальной тяжести. Визуальная проверка и замеры FPS не выполнялись.

## Карта и легенда

Карта находится в стартовом ящике X=0, Z=−7, весит 0,1 кг и занимает один слот. Открывается на M или кнопкой «Открыть» на карточке предмета. В верхней части панели показаны координаты игрока X/Z; на основном экране координат нет. Просмотр ставит игру на паузу и скрывает HUD; M или крестик в правом верхнем углу возвращает управление, I переключает к инвентарю, Escape — к меню.

На карте только исследованная местность, иконки автоматически найденных мест, стрелка игрока и север. Рядом — легенда пяти типов мест: стартовая база, жилище, пост, караван, оазис. Поясняющие абзацы и список найденных мест удалены. При открытии карта центрируется по игроку; обзор перемещается мышью или пальцем. Есть «К себе» и масштабы +/− (384/768/1536 м по ширине). Панель помещается по высоте окна без общей вертикальной прокрутки, квадрат карты уменьшается под доступное место; легенда при необходимости прокручивается отдельно, на узком экране располагается под картой.

Изначально карта пустая. При наличии предмета открывается область 3×3 клетки: клетка игрока и восемь соседних, включая диагональные. Размер клетки уменьшен с 32×32 до 16×16 м, поэтому высота и вода отображаются подробнее; запись выполняется с проверкой раз в 0,5 с. Старые маршруты до получения карты не раскрываются. Предел — 80 000 клеток; увеличение вчетверо сохраняет прежнюю предельную исследованную площадь после повышения детализации. Повторный осмотр не добавляет дубли, у границ мира соседние клетки ограничиваются допустимой областью. Пройденная местность остаётся открытой после выбрасывания карты, новые участки без карты не записываются.

База, жилища, посты и караваны обнаруживаются в пределах 16 м от центра; оазисы — в пределах 1,8 радиуса асимметричного берега. Это обнаружение по близости, без проверки видимости. Открытия сохраняются сразу, не дублируются; предел — 2000 мест. Генерируемый мир целиком заранее не раскрывается.

Ручные метки и карандаш (набор для меток) удалены. Предмет не генерируется, его иконки и отображения в мире нет. Актуальная схема 19 сохраняет клетки карты и автоматические открытия; загрузки прежних схем и миграции ручных меток нет.

Расчёты карты находятся в `features/navigation`, интерфейс — в `ui/navigation`. Визуальная проверка и замеры FPS не выполнялись.

## Температура, состояния организма и стартовый лагерь

Активны обезвоживание, истощение, перегрев и переохлаждение. У каждого состояния три видимые степени: лёгкая, тяжёлая и критическая; несколько состояний могут сочетаться. В HUD показаны название, тяжесть и способ восстановления, в инвентаре — дополнительные симптомы. Внутренняя накопленная тяжесть не отображается как здоровье.

Обезвоживание постепенно нарастает при воде ниже 25, истощение — при сытости ниже 20. Чем ниже запас, тем быстрее ухудшение. Для восстановления нужно поднять соответствующий запас до 35 или выше; отдых ускоряет восстановление накопленной слабости. Один приём еды/воды не снимает симптомы мгновенно. Состояния замедляют движение и восстановление сил; истощение уменьшает доступную выносливость и устойчивость к холоду. Накопленные состояния сохраняются при перезапуске и стоят на паузе в меню и скрытой вкладке.

Температура воздуха интерполируется по таблице концепции: 00:00 +13 °C, 03:00 +8 °C, 06:00 +11 °C, 09:00 +27 °C, 12:00 +40 °C, 15:00 +45 °C, 18:00 +32 °C, 21:00 +19 °C. Температура тела изменяется постепенно. Солнечный нагрев усилен и настроен с характерным временем 3⅓ игрового часа (400 реальных секунд при текущих сутках); обычный температурный отклик, охлаждение в тени, воде и укрытии сохраняют характерное время 120 реальных секунд. Это время отклика, а не фиксированный таймер до перегрева. На неё влияют солнце, тень, ветер, движение/бег, груз, вода и уже накопленные состояния. Вода охлаждает, особенно в холодное время; обезвоживание усиливает нагрев, перегрев повышает расход воды: накопленная тяжесть даёт множитель от ×1 до ×3, дополнительный расход от повышенной температуры тела сохраняется. В HUD вместо градусов воздуха показан одна полоска с синим холодом слева, оранжевым перегревом справа и ползунком посередине при нормальном состоянии. Крестик отражает самое тяжёлое состояние организма. Перегрев начинает накапливаться после прогрева тела выше +37,7 °C, переохлаждение — ниже +36 °C; тень и укрытие снижают нагрев, накопленное состояние проходит постепенно после охлаждения. Головной убор сильно замедляет солнечный нагрев. Ориентир начала риска — 1–2 игровых часа без головного убора и 3–4 с ним. В расчётной проверке при +40 °C, полном солнце, ветре 3,5 м/с, обычной ходьбе, нормальной исходной температуре тела и без тёплой одежды получено 135 с (1,125 игрового часа) и 376,75 с (3,14 часа) соответственно. Утром, в тени или при другом ветре время меняется; спринт, груз и обезвоживание могут ускорять нагрев. Это расчётная проверка, баланс прохождением ещё не подтверждён. Активны экипируемая одежда, костёр и сон на кровати.

Головной убор (0,15 кг) уменьшает солнечную составляющую нагрева на 65%, но не защищает от горячего воздуха или обезвоживания. Тёплая одежда (1,2 кг) уменьшает охлаждение от холодного воздуха на 70% и действие ветра на 65%; выше +22 °C постепенно добавляет нагрев, до +0,5 °C к целевой температуре тела при +35 °C. Охлаждение в воде сохраняется. Это предварительные параметры, баланс ещё не проверен. Обе вещи можно забрать в стартовом ящике X=0, Z=−7; дополнительные головные уборы иногда встречаются в жилищах, тёплая одежда — на постах. В мире пока используются простые цветные формы.

В инвентаре (I) нажмите «Надеть» или «Снять»; замена возвращает прежнюю вещь в освободившийся слот. Защита действует только от надетых вещей. Они не занимают слоты инвентаря, но их вес учитывается в перегрузе, подборе и наборе воды. Снятие требует свободного слота только если такой группы ещё нет в инвентаре, а также соблюдения предела массы; затем вещь можно оставить на земле и подобрать снова. Одежда сохраняется вместе с остальными припасами.

Игровая тень рассчитывается по направлению того же солнца, которое рисуется на небе: проверяются коллайдеры и рельеф до 60 м; кроны пальм приближённо считаются дисками, их покачивание не копируется. Это ограниченная игровая модель, она не считывает графическую карту теней и не зависит от её разрешения. Совпадение игровой и видимой тени нуждается в ручной проверке. Ночью прямого солнечного нагрева нет.

Для противодействия температуре добавлен постоянный стартовый лагерь около X=0, Z=−18. Это открытый навес 6×5 м на четырёх стойках с крышей высотой 3,2 м и входом со всех четырёх сторон; игровая модель укрытия сохраняет тень и защиту от ветра; внутри температура тела постепенно возвращается к безопасному диапазону. Он не создаёт воду или еду и не ускоряет игровое время. Крыша и стойки используют общие данные для изображения, коллизий и тени; при прыжке голова упирается в крышу. Если старая сохранённая позиция оказалась внутри новой стены, при загрузке выполняется поиск свободной позиции рядом. Стартовый и переносной навесы используют общее построение крыши и четырёх стоек. Крыша стартового навеса отсчитывается от максимальной высоты песка на его участке, а не от высоты центра. Лагерь отображается поблизости одним instanced mesh из пяти частей; ресурсы освобождает React Three Fiber при выгрузке. Это поддержка первого маршрута; отдельно доступен размещаемый переносной навес, восстановление базы ещё не реализовано.

Критическая степень сейчас означает сильные штрафы и предупреждение. Потеря сознания, смерть и таймер до проигрыша ещё не включены: последствия проигрыша предстоит выбрать отдельно. Ни текущая сборка, ни описание модели не подтверждают баланс температуры, совпадение тени и внешний вид лагеря в браузере.

## Подбираемые осколки — прототип entitymate

**Временно скрыто.** Флаг `GAME_FEATURES.resourceCollection` в `src/app/gameFeatures.ts` установлен в `false`: система предметов не монтируется, объекты, счётчик, предупреждения и подсказка E не отображаются, обработчик подбора не подключается. Сохранение осколков не читается и не изменяется. Реализация, зависимость `entitymate` и тесты сохранены для дальнейшего использования. Для возвращения механики установите флаг в `true`.

При включении на песке встречаются янтарные осколки. Первый расположен в X=0, Z=−6, прямо перед исходной точкой старта. Подойдите ближе и нажмите E: подсказка появляется в пределах 3 м от камеры до центра предмета. В HUD показано общее число находок. Подбор возможен только во время игры с захваченным курсором; удержание E не собирает предметы автоматически. Осколки не блокируют движение.

`features/resources/resourceGeneration.ts` детерминированно задаёт до трёх предметов на чанк с ID `shard:v1:cx:cz:slot`. Подводные места и пересечения с коллайдерами декораций исключаются. `resourceStore.ts` использует закреплённую версию `entitymate` 0.2.0: `set` заменяет ближайшие 3×3 чанка, `update` отмечает подбор, индекс `collected` отделяет доступные предметы. Активно не более 27 записей; при уходе из области записи выгружаются. Существующий индекс камней и растительности не меняется.

Сразу после подбора приложение записывает только версию и уникальные ID собранных осколков в `localStorage` под ключом `desert-walker.resources.v1`. При возвращении и перезапуске эти изменения применяются к заново сгенерированным предметам. Счётчик выводится из набора ID, поэтому повторный подбор не увеличивает его. Набор изменений растёт с числом находок; весь сгенерированный мир не сохраняется. Сохранение локальное для браузера и адреса игры. Для смены схемы размещения нужна новая версия или миграция ID.

Повреждённая запись игнорируется с сообщением в HUD; новый подбор начинает новое сохранение осколков. При отказе хранилища игра сохраняет изменения в памяти и показывает предупреждение. Повторная запись выполняется при следующем подборе, скрытии страницы, уходе с неё и размонтировании системы.

Осколки рисуются одной инстансированной сеткой с общей геометрией и материалом, которыми владеет React Three Fiber и которые он освобождает при размонтировании. Матрицы обновляются при смене области и подборе. Проверка близости выполняется 10 раз в секунду; изменения коллекции и запись в хранилище не выполняются каждый кадр. Тесты `npm test` проверяют API установленного пакета, ограничение активных объектов, радиус и повторный подбор, уход/возвращение, перезапуск, повреждённые сохранения и отказ/восстановление хранилища.

Встроенный браузер в текущей среде не подключается (`missing field sandboxPolicy`); визуальная проверка осколков и интерфейса и замеры FPS не выполнены. Сборка и автоматические проверки не подтверждают графику или производительность в браузере.
